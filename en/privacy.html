Privacy Policy

Last updated: November 12, 2026 · Version française

In short. Statistics are saved only on the PC, in a local SQLite database. Access tokens are kept in Windows Credential Manager.

For TikTok, a small server (the “broker”, on Cloudflare Workers) exchanges and refreshes tokens, as TikTok requires. Tokens therefore pass through this server, which keeps the refresh token encrypted. No statistics go through it.

No data is sold, shared or used for advertising.

1. Who this covers

Pulse Studio is a personal, free, non-commercial Windows desktop application. It is not sold or distributed, and it has no user accounts. Its developer uses it only to track the statistics of their own accounts.

On TikTok, the application runs in sandbox mode: only accounts owned by the developer can connect to it. This policy therefore describes how the data of those accounts is handled.

3. Data read

Only the data needed for the dashboard is requested, with read-only permissions.

PlatformPermissionsData read and saved
TikTok user.info.basic, user.info.stats, video.list

Account: app-specific account identifier (open_id), display name, follower count, total likes received, number of public videos.

Public videos: identifier, title or start of the description (150 characters at most), publication date, duration, cover image URL, share link, view, like, comment and share counts.
YouTube YouTube Data API v3 key (public data, no account sign-in) Videos: identifier, title, thumbnail, publication date, duration, channel name, views, likes, comments. Channel: subscribers, total views, number of videos.
Instagram, Facebook Planned, not active yet No data is read today. This policy will be updated before they are enabled.

Never read: private videos, drafts, messages, comment content, viewer data (identity, location, age), email address, phone number, contacts. Pulse Studio requests no permission to post or modify anything.

4. Local storage

  • The data above is saved in a SQLite database on the PC, in the application’s data folder (%APPDATA%\com.pulsestudio.app\pulse.db).
  • The database holds successive readings and the stabilized history (a temporary drop is only kept once confirmed), which feed the charts.
  • The database is not sent to any server. Any backups are local copies made by the user.

5. Tokens and credentials

  • On the PC, in Windows Credential Manager: the TikTok access token (valid for about 2 hours), the YouTube API key and the device key, which authenticates the PC to the broker.
  • Tokens are never written to the SQLite database, logs, source code or user interface.
  • On the broker (see section 6): the TikTok app secret, which is never present on the PC, and the TikTok refresh token, encrypted.

6. Cloudflare broker

TikTok requires the exchange of the authorization code for tokens, and their refresh, to use the app secret and to happen on a server. For this, Pulse Studio uses a small service, the “broker”, hosted on Cloudflare Workers (free plan).

Details
What passes through During sign-in: the authorization code, the PKCE verifier and the local redirect address. Then the tokens returned by TikTok and the open_id. The access token is passed back to the PC.
What is kept
  • The TikTok refresh token, encrypted with AES-256-GCM and linked to the open_id.
  • One-time identifiers (“nonces”), for 10 minutes, to block replayed requests.
  • For Instagram and Facebook, once active: the encrypted sign-in result, for 10 minutes at most, erased as soon as the PC has collected it.
What never goes through it Statistics, videos, their titles and the history: the PC reads them directly from the official APIs.
Logs The broker’s invocation logs are disabled, and its code writes nothing to the console. As the host, Cloudflare processes the technical data of requests (IP address, headers) under its own privacy policy.
Status As of the update date, the broker is built and tested but not yet online.

7. Third-party services

  • TikTok (open.tiktokapis.com, sign-in pages on tiktok.com) and Google / YouTube (googleapis.com) receive the requests sent by the PC. They handle them under their own policies.
  • Cloudflare hosts the broker.
  • GitHub hosts this website (see section 12).

8. Sharing and use

The data is used only to show, on the PC, how the statistics of the developer’s accounts change over time. It is not sold, rented or shared. It is not used for advertising or profiling, and it is not used to train models. The application contains no analytics, telemetry or automatic error reporting.

9. Retention

  • Local database: until the user deletes it. Disconnecting keeps the history already recorded.
  • TikTok access token: about 2 hours. It is replaced at each refresh and deleted on disconnection.
  • TikTok refresh token (broker): until disconnection, revocation, or the expiry set by TikTok.
  • Nonces and sign-in results (broker): 10 minutes at most.

10. Disconnection and deletion

  • “Disconnect”, on the application’s Connected accounts page:
    • the broker first erases the refresh token, then revokes access with TikTok;
    • the local token is deleted from Credential Manager;
    • TikTok is paused.
  • Access can also be removed at any time from the TikTok account settings, in the management of authorized apps.
  • To delete the whole local history, delete the pulse.db file while the application is closed. The YouTube history can also be cleared from within the application.

11. Security

  • All network traffic is encrypted (HTTPS). Only the TikTok sign-in callback arrives locally, on http://127.0.0.1, as TikTok specifies for desktop applications.
  • TikTok sign-in uses PKCE and a verified state parameter.
  • Every request from the PC to the broker is signed (HMAC-SHA256), timestamped and single-use. The request rate is limited.
  • Permissions are minimal and read-only.

12. This website

This website is static and hosted by GitHub Pages. It uses no cookies, scripts, analytics or external resources. GitHub may record technical visit data (such as the IP address) under its own privacy statement.

13. Changes and contact

This policy will be updated whenever data handling changes, in particular before Instagram and Facebook are enabled. The update date is shown at the top of the page.

For any question, open an issue on the public GitHub repository that hosts this website.
